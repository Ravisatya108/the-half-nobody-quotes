I run my working life out of a folder of plain-text files. About ninety small thinking systems live there now, built one at a time with an AI in a terminal: decision protocols, prediction ledgers, watch lists aimed at the outside world, published reference pages, a memory index. The folder is very good at accumulating. It turned out to be terrible at remembering that it had promised to do things.

The discovery that changed the architecture is one sentence long, and it is now written into the documentation of the scripts it produced: "a review date in a markdown file is a wish; markdown files do not ring." I had files full of settle-by dates, check-by dates, review-on dates. None of them ring. A text file reads exactly the same the day after its deadline as the day before it, and it will wait politely forever.

So I built ringers. Eight small Python scripts that run at the end of every working session, each watching a different way things rot when nobody is looking. One watches the list of things I claimed were blocking me; if that list goes "30+ days old with ZERO receipts and ZERO declines," it declares the list dead. Its documentation calls this the dead-man switch and notes that it is "The only verdict in the corpus the operator did not author — the calendar writes it." Another — the firing pin — watches commitments about money, the ones with maturity dates and conditions attached, on the principle that "a file in your own vault is not an external filing." Another checks whether my watches on the outside world ever actually run; its gravest finding, the dark-tower clause, fires when a watch has sat open for a month with no report filed, because "a sensor that never runs emits false confidence." Another scores my written predictions once their resolution dates pass — "a verdict that is never scored is an opinion with a filing system" — and calls a prediction file that never settles "a diary with a scoring rubric stapled to it." Another compares every page I have published against the file it was published from, because "a vault file and its published twin are two objects — editing one does not move the other." The rest watch session records, a hand-written summary that quotes other documents, and my own memory.

One law sits over all of them, in capitals at the top of their shared manual: "ALL ADVISORY, NEVER BLOCKING." No check may ever stop work. "A red here means write the missing thing, never stop shipping." Behind that sits the law I trust most in the whole folder: "structural fixes never recur; vigilance fixes always do. A warning nobody reads is silent machinery — and a warning that's 85% noise is worse than none." A blocking check gets bypassed. A noisy check gets ignored. Either way it stops being a conscience and becomes furniture. So each script does one thing: it exits zero when all is well, and non-zero with a finding when something has rotted.

For weeks, the end-of-session sweeps came back clean on most rows, and I read those clean lines the way you read a smoke detector's silence — as news that nothing is burning.

Then, this week, I built the newest of them — the one aimed at my own memory. It tests whether things I formatted to be remembered actually survive there, on the theory that "the shape that feels held and the shape that holds are different shapes, and only delay separates them." Building it forced one small engineering decision: how to parse the metadata block at the top of each file it reads. The easy answer is the library everyone reaches for, PyYAML. The script refuses it and carries its own tiny parser instead, and its documentation gives the reason: "a conscience that exits 0 on an ImportError is itself a dark tower."

That sentence was not a hypothesis. The same paragraph continues: "that is not hypothetical: proofledger-check, watchtower-check and underwriter-check were found doing exactly that on this machine, 2026-08-06, reading CLEAN in every closing pass." Here is the mechanism, in full, because it is the whole story. The Python installation on this machine does not have PyYAML. Three of the eight watchdogs — the firing pin, the world-watcher, the prediction scorer — import it, hit the missing library, catch the error, and exit 0. In the quiet mode the closing sweep uses, each printed one line to a stream nobody reads and reported success. The note filed that day gives the verdict: "The dead-man switches are themselves dead."

Sit with the ironies for a moment, because each one is a lesson wearing a costume. The script whose founding line is that an unscored verdict is "an opinion with a filing system" was itself scoring nothing. The script that named the dark tower — a sensor that never runs, which "emits false confidence" — had become one. And the operations manual for this whole apparatus keeps a standing section titled "Honest limits — what the machinery does NOT catch," a written confession of its own blind spots. This failure was not on the list. The blind-spot list had a blind spot.

How long were the three dead? I cannot say, and that is the sting. A check that fails open leaves no record of when it stopped checking. Weeks of closing summaries printed clean lines for those three rows, and I no longer know which of those clean lines were earned and which were the sound of nobody looking.

If you build automated checks of any kind — CI gates, monitors, data-quality tests, a cron job that sanity-checks a backup — the general form of this failure is worth stating plainly. Exit code 0 is doing double duty. It means "I looked and found nothing," and it also means, unless you explicitly forbid it, "I could not look." Every library your watchdog imports, every file it assumes exists, every credential it needs, is a way for it to die before the watching starts — and if it dies politely, it dies into the same silence that health produces. The fixes are unglamorous: a watchdog's own setup failure must be a loud red, never a zero; where you can, make the detector prove it ran rather than merely not complain. My newest script's answer was the paranoid one — depend on nothing you cannot carry yourself.

I gave my second brain a conscience because I learned that files do not ring. Then I learned the harder half: scripts do not ring either, when the failure is their own. A detector that fails open is indistinguishable from a world with nothing wrong — which is why the first thing any watchdog must be able to detect is its own failure to watch.

*Method note, plainly: this came out of a folder's end-of-session checking discipline; every quoted line is verbatim from the scripts' own operating manuals or from the note filed the day three of them were found asleep.*
